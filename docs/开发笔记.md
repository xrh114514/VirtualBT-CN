## 1. Win11 24H2+ 的 `CoreApplication.MainView` fail-fast

**症状**：扫描页点「开始」约 5 秒后闪退。WER 报 `combase.dll` + `0x800710DF`（`ERROR_NO_TASK_QUEUE`）。

**原因**：从 **线程池线程** 访问

```csharp
Windows.ApplicationModel.Core.CoreApplication.MainView.CoreWindow.Dispatcher
```

在 Windows 11 24H2+（build 26200）会直接 fail-fast，连异常都抛不出来。BLE watcher 的 `Received` / `Added` 回调都在线程池线程上，原代码有 20 处这样的调用。**Template10 的 `Dispatcher.DispatchAsync` 内部也是同样的写法**，所以单纯替换项目内代码不够。

**解法**：`Models/SafeDispatcher.cs` 在 UI 线程缓存一次 `CoreDispatcher`，任何线程都用 `SafeDispatcher.Current` / `SafeDispatcher.RunAsync`。必须在 `App.OnInitializeAsync` 里 `SafeDispatcher.Initialize(Window.Current.Dispatcher)`（早于任何 watcher 回调）。

**注意**：`SafeDispatcher.cs` 要在 `VirtualBT.csproj` 的 `<Compile>` 里显式声明（老式 csproj 不会自动包含）。

## 2. 蓝牙监视器不能 `Stop()` 后复用

**症状**：勾选「持续扫描」后偶发闪退，同一 `0x800710DF`。

**原因**：`BluetoothLEAdvertisementWatcher` 调 `Stop()` 再立即 `Start()`，与 WinRT 内部任务队列销毁竞态。

**解法**：`StartAdvertisementWatcher` 每次 **新建** watcher 实例，`StopAdvertisementWatcher` 里取消事件订阅后 `Stop()` 并置空。`AdvertisementWatcher_Received` 开头校验 `sender` 是否仍是当前 watcher，丢弃迟到回调。

---

## 3. `SemaphoreSlim` 不能在 `finally` 里无条件 `Release()`

`async void` 的事件回调里，如果 `WaitAsync` 之前的代码抛异常，`finally` 中 `Release()` 一个从未获取的信号量会抛 `SemaphoreFullException`，进程直接死。

**解法**：`bool lockTaken` 标志，只在真正获取后才释放。

## 4. 汉化 / 本地化的三个坑

### 4.1 `x:Uid` 不覆盖 XAML 字面值

`x:Uid="Str_X"` + `Resources.resw` 里的 `Str_X.Text` **不会覆盖** `Text="扫描设备"`。必须把字面值属性删掉，只留 `x:Uid`。

### 4.2 资源 key 编译后是 `uid/Property`（斜杠）

`ResourceLoader.GetString("Str_X.Text")` 返回空字符串；`GetString("Str_X/Text")` 才对。`Models/Loc.Get` 内部做了 `.` → `/` 的替换。

验证方法（在包内跑 PowerShell）：

```powershell
Invoke-CommandInDesktopPackage -PackageFamilyName <PFN> -AppId 'App' `
  -Command 'powershell.exe' -Args '-NoProfile -File <脚本>'
# 脚本里：ResourceLoader.GetForViewIndependentUse().GetString('Str_X/Text')
```

### 4.3 `ComboBoxItem IsSelected="True"` 会覆盖保存的语言

`IsSelected="True"` 在 `InitializeComponent()` 期间触发 `SelectionChanged`，把刚保存的 `en-US` 写回 `zh-CN`，每次启动都重置。

**解法**：`m_initializing = true` 必须在 **`InitializeComponent()` 之前** 设置；XAML 里去掉 `IsSelected`；`ApplyStoredLanguage()` 只在有显式设置时才应用，不要强制默认值（否则会覆盖重启前刚设的 `PrimaryLanguageOverride`）。

### 4.4 其它

- **XAML 枚举属性值不能翻译**（如 `Stretch="None"`、`ConverterParameter=Hex`），否则 XAML 编译器报错或转换器失效。
- `<x:String>值</x:String>` 没有依赖属性可被 `x:Uid` 赋值，用 `Models.LocalizedString`（有 `Value` 属性）替代。
- `.ps1` 脚本里的中文必须带 BOM 或用 GBK 保存，否则 PowerShell 5.1 按 ANSI 读取会乱码甚至报错。

## 5. 鼠标捕获：相对位移与键盘隔离

`Windows.UI.Input.MouseDevice.MouseMoved` 在这个 UWP 投影里解析不出来（`CS0246`），改用 `CoreWindow.PointerMoved` 的**位置差值**推算相对位移。

**副作用**：指针到达窗口/屏幕边缘时不再上报（UWP 没有 `ClipCursor`），而且指针顶到屏幕上边缘会把全屏标题栏带出来。

**缓解方案（v1.2.0）**：指针进入边缘 48 DIP 范围内时，把它弹回所在显示器的中央，位移继续上报，指针也不会再顶到上边缘带出标题栏。弹回用 **`user32!SetCursorPos`**（`Models/SystemPointer.cs`）：目标取 `MonitorFromPoint(GetCursorPos())` 所在显示器的中心，任意多显示器布局都精确；目标与当前位置取自同一坐标空间，因此不必关心 DIP/物理像素。弹回产生的跳变会被吞掉（回弹在途时任何 ≥ 120 DIP 的位移视为跳变），400 ms 超时后重置基准点，防止弹回失败时移动永久失效。

**不要用注入的相对位移来做这件事。** `InputInjector` 的相对 `DeltaX/DeltaY` 会经过 Windows 鼠标加速度缩放——实测默认桌面下请求 60 单位实际走 146 px、请求 −30 单位走 64 px，比例在 2~2.5 倍之间还不固定——"拉回中心"会**过冲出窗口**，表现就是弹回完全没生效。注入的**绝对**位移是精确的，保留为后备：`DeltaX/DeltaY` 是按**主显示器**归一化的 0–65535（32768,32768 精确落在主屏中心，已逐像素验证），多显示器下会弹到主屏，但只在 user32 不可用时才会走到。

`InputInjector.TryCreate()` 作为后备，需要在 `Package.appxmanifest` 里声明下列能力。注意 `CT_Capabilities` 是**严格序列**，`rescap:Capability` 必须放在 `DeviceCapability` **之前**，否则 `APPX0501` 校验失败：

```xml
<rescap:Capability Name="inputInjection" />
<DeviceCapability Name="bluetooth" />
```

两种机制都不可用时，界面会提示并退回旧行为（指针到边缘停止）。状态行始终显示当前用的弹回方式（`回中 win32` / `回中 injector` / `回中 none`）。

**全屏 chrome**：先设 `FullScreenSystemOverlayMode = Minimal`（19041 投影只有 `Standard`/`Minimal`），再尝试 `Hidden`（值 2）并**读回确认**——不认识该值的系统会停留在 `Standard`，而 `Standard` 正是"指针到上边缘滑出标题栏"的那一档。部分系统无论设什么浮层照样弹出，所以呈现方式本身也可切换（见下）。

### 5.1 两种全屏呈现（设置 → 游戏模式全屏）

**无边框窗口全屏（默认）** = `ApplicationView.TryEnterFullScreenMode()`，DWM 合成的无边框窗口铺满屏幕。系统仍保留一条隐藏标题栏，指针到屏幕上边缘会把它带出来。

**独占全屏** = UWP XAML 应用能做到的最接近游戏独占全屏的形态（没有 DirectX 交换链可以交给 `DXGI::SetFullscreenState`）：把顶层窗口改成铺满显示器的无边框置顶窗口，并去掉 `WS_CAPTION | WS_THICKFRAME | WS_SYSMENU | WS_MIN/MAXIMIZEBOX`。没有可呼出的标题栏，也没有可误点的窗口按钮。

两个关键事实：

- **UWP 应用的可见窗口归 `ApplicationFrameHost.exe` 所有。** 顶层 `ApplicationFrameWindow` 属于另一个进程，应用自己的 `CoreWindow` 是它的子窗口（`EnumWindows` 看不到应用有任何顶层可见窗口）。因此样式要改在 `GetAncestor(ICoreWindowInterop.WindowHandle, GA_ROOT)` 上，即**跨进程** `SetWindowLong`。对运行中的应用实测有效：`SetWindowLong` 成功，caption 位真的被去掉（`0x94CF0000` → `0x94030000`）。
- **`ICoreWindowInterop`（`45D64A29-A63E-4CB6-B498-5781D298CB4F`）** 是拿 CoreWindow HWND 的唯一途径。注意 C# 里不能把投影类 `CoreWindow` 直接强转成 `ComImport` 接口（`CS0030`），要**经 `object` 中转**，让强转变成运行时 QueryInterface。

`FullscreenMode.TryEnterExclusive()` 之后会读回样式验证，任何一步失败都还原已保存的样式/位置；捕获页在它返回 false 时回退到无边框窗口全屏。离开捕获模式时 `LeaveExclusive()` 原样还原窗口——该路径**不要**调 `ExitFullScreenMode`，因为压根没进过 `ApplicationView` 全屏。

**键盘隔离**：捕获期间任何按键都不能落到电脑端窗口上（快捷键、Tab 焦点、文本输入）。只挂 `CoreWindow.KeyDown` **不够**——它与 XAML 自己的处理是并行的。真正拦住 XAML 的是 `CoreWindow.Dispatcher.AcceleratorKeyActivated` 置 `args.Handled = true`（外加 `CharacterReceived.Handled`）。退出快捷键在两条路径都判断（`ExitCapture` 幂等）。转发只在 `CoreWindow.KeyDown/KeyUp` 里做（只有这里有 `KeyStatus.ScanCode`），且**只有按下时转发过的键才转发释放**，避免本地吞掉的按键在手机端卡住。离开时再调 `VirtualKeyboard.ReleaseAllKeys()` 兜底。

**Shell 侧边栏**：`HideShellChrome()` 在捕获期间收起 Template10 `HamburgerMenu`（`HamburgerButtonVisibility = Collapsed`、`DisplayMode` 和三个 `VisualState*DisplayMode` 都设为 `Overlay`、`IsOpen = false`），离开时还原保存的值。**三个视觉状态模式都要设**——控件代码后置会在窗口宽度变化时重新套用 `DisplayMode`，只改一个侧边栏会再冒出来。指针事件并没有置 Handled，隐藏侧边栏是因为捕获时点到导航按钮会直接导航离开。

## 6. HID 报文格式

Report Map 包含两个集合：

| Report ID | 用途 | 载荷（不含 ID 字节） |
|---|---|---|
| 1 | 键盘 | `修饰键(1) + 按键(7)` = 8 字节 |
| 2 | 鼠标 | `按键(1) + X_lo, X_hi, Y_lo, Y_hi + 滚轮(1)` = 6 字节 |

每个 Report ID 有独立的 Report Value 特征 + Report Reference 描述符（`0x2908`），载荷里**不**含 Report ID 字节。

键盘码转换：`HidHelper.GetPs2Set1ScanCodeFromStatus`（PS/2 set-1 → HID usage），键盘页与捕获页共用。

`VirtualKeyboard.CapturePageOwnsKeyboard` 静态标志用于让键盘页的 `CoreWindow` 处理器在捕获页激活时让路，避免同一按键上报两次。

## 7. 构建环境

- **VS Community 2022** + `Microsoft.VisualStudio.Workload.Universal`（Build Tools 2022 不含 UWP 工作负载）
- `.NETCore v5.0` 引用程序集 VS 没装上，从 NuGet `ref/netcore50` 汇集到 `deploy/refasm/`，编译时用 `-p:TargetFrameworkRootPath` 指过去
- .NET Native 1.6 运行时 appx 在 `deploy/nuget/`（来自 `Microsoft.Net.Native.SharedLibrary-x86` 1.6.1 与 `Microsoft.Net.Native.Compiler` 1.6.2）
- 编译产物在 `bin/x86/Release/ilc/`，拷到 `deploy/AppX` 后重新注册

发版打包：`python deploy/pack_dist.py <版本号>` 会刷新 `deploy/AppX`、组装 `deploy/dist/VirtualBT-CN-v<版本号>/`（文档 + 启动脚本 + 去掉 pdb/g.cs 的 `deploy/AppX` + `deploy/nuget` 运行时 appx）并压成 zip。**必须**用 Python 的 `zipfile`：`Compress-Archive` 写中文文件名时不带 UTF-8 标志位，解压后会乱码。

详细命令见 [README.zh-CN.md](../README.zh-CN.md)。
